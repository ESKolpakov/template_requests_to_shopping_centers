# Письма в УК ТЦ

Локальное Windows-приложение для ГБУ «МКМЦН»: формирует пакет писем «Об
оказании содействия» в управляющие компании торговых центров — по одному
письму на адрес здания, — на основе Excel-выгрузки объектов торговли и
справочника контактов УК/ТЦ. Умеет полуавтоматически доразведывать данные
об УК через ЕГРЮЛ и ведёт реестр результатов генерации.

Реализовано строго по техническому заданию — см. [docs/SPEC.md](docs/SPEC.md).

## Возможности

- **Шаблоны** — свой .docx с плейсхолдерами вместо переменных данных;
  оформление (шрифты, отступы, стили таблиц) сохраняется 1-в-1, потому
  что заполнение идёт прямо в текстовых узлах документа, а не пересборкой
  через API. См. [docs/TEMPLATE_GUIDE.md](docs/TEMPLATE_GUIDE.md).
- **Источники данных** — «сырая» выгрузка «Реестр ТО» из АИС ОПН (без
  предобработки) и справочник контактов УК/ТЦ, загружаются и
  перезагружаются независимо друг от друга.
- Группировка объектов по зданию, объединение строк одного объекта в
  таблице письма (rowspan), нормализация и сопоставление адресов между
  источниками устойчивое к разному порядку слов и сокращениям
  («ул.»/«улица», «Парковая 9-я»/«9-я Парковая» и т.п.).
- Персональный адресный блок со склонением ФИО в дательный падеж
  (pymorphy3) и определением пола, обезличенный вариант — когда данных об
  УК нет; словоформы единственного/множественного числа по числу
  хозяйствующих субъектов в письме.
- Расчёт срока предоставления информации с переносом на рабочий день по
  редактируемому списку праздников.
- Полуавтоматическая проверка по ЕГРЮЛ: приложение подставляет ИНН в
  форму поиска на egrul.nalog.ru и разбирает уже скачанный пользователем
  PDF (текстовый слой) — без обхода капчи и без скрапинга.
- Реестр (лог) генерации, сохраняющийся между запусками (SQLite).

## Приватность

Это открытый репозиторий. В нём **нет и не должно быть**:

- реальных писем-образцов, выгрузок Excel или PDF-выписок ЕГРЮЛ
  (все они содержат ФИО, ИНН, телефоны, адреса конкретных людей и
  организаций);
- реального бланка/шаблона письма (даже без личных данных — это
  официальный документ-бланк учреждения, публикуется по решению
  постановщика задачи только внутри организации, не в открытом
  репозитории);
- персональных данных сотрудника-исполнителя — поля «Исполнитель»,
  «Телефон исполнителя», «Подписант» в коде по умолчанию **пустые** и
  заполняются один раз в разделе «Настройки» — сохраняются только
  локально в `config.json` в пользовательском каталоге данных (см.
  `src/uktc_letters/paths.py`), не в репозитории.

Всё, что приложение сохраняет между запусками (настройки, реестр
генераций, кэш проверок по ЕГРЮЛ, скопированный шаблон), лежит в
стандартном пользовательском каталоге приложения ОС, а не в каталоге
исходников — `.gitignore` дополнительно исключает файлы `.docx`/`.xlsx`,
`config.json`, `registry.sqlite3`, `egrul_cache.json` от случайного
попадания в репозиторий.

### Как проверить на своих данных

1. Возьмите свой реальный бланк письма и подготовьте из него шаблон по
   инструкции в [docs/TEMPLATE_GUIDE.md](docs/TEMPLATE_GUIDE.md) —
   загрузите через вкладку «Шаблоны».
2. Загрузите свою выгрузку «Реестр ТО» и справочник УК/ТЦ на вкладке
   «Источники данных».
3. Заполните «Настройки» (исполнитель, телефон, подписант) один раз.
4. Сгенерируйте письма на вкладке «Генерация писем».

## Установка и запуск (из исходников)

```bash
python -m venv .venv
. .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
PYTHONPATH=src python -m uktc_letters.main
```

## Сборка в единый .exe (Windows, без установки Python у пользователя)

```bash
pip install -r requirements-dev.txt
pyinstaller scripts/build_exe.spec
```

Результат — `dist/UKTCLetters/UKTCLetters.exe`.

## Тесты

```bash
pip install -r requirements-dev.txt
PYTHONPATH=src:tests pytest tests/ -v
```

Тесты используют только синтетические данные (см. `tests/fixtures.py`) —
вымышленные названия организаций, ИНН и адреса в формате, идентичном
реальным источникам, без единого реального персонального данного.
Модуль разбора ЕГРЮЛ-выписок и весь конвейер генерации писем (адресация,
группировка, словоформы, rowspan-объединение таблицы) дополнительно были
проверены вручную на реальных файлах-примерах из технического задания —
эти файлы в репозиторий не включены (см. «Приватность» выше).

## Архитектура

```
src/uktc_letters/
  addresses.py       — нормализация и отображаемое форматирование адресов
  objects_source.py  — разбор "Реестр ТО" + группировка по зданию
  contacts_source.py — разбор справочника УК/ТЦ + сопоставление адресов
  morphology.py       — склонение ФИО, определение пола, словарь должностей
  dates.py             — расчёт срока с переносом на рабочий день
  egrul_parser.py       — разбор PDF-выписок ЕГРЮЛ
  egrul_cache.py         — локальный кэш подтверждённых результатов ЕГРЮЛ
  formatting.py            — форматирование ФИО/организаций/адресов для письма
  docx_template.py          — заполнение .docx-шаблона (плейсхолдеры + rowspan)
  letters.py                 — оркестрация: план одного письма по зданию
  naming.py                   — имя файла итогового письма
  config.py                    — настройки приложения (раздел 7 ТЗ)
  registry.py                   — реестр результатов генерации (SQLite)
  paths.py                       — расположение пользовательских данных
  gui/                             — Tkinter-интерфейс (5 вкладок по ТЗ)
```

Ключевое архитектурное решение — модуль `docx_template.py` не собирает
письмо заново через API `python-docx` (это неизбежно теряет мелкие детали
вёрстки), а находит и подменяет текст плейсхолдеров прямо в существующих
текстовых узлах документа, который загрузил пользователь. Строка таблицы
объектов клонируется по числу нужных строк с простановкой `vMerge` для
столбцов, объединяемых для нескольких хозяйствующих субъектов одного
объекта — так же, как это сделано в оригинальных письмах-образцах.

## Известные упрощения

- Автоматическое переупорядочивание названия улицы с числительным в
  начале («Парковая 9-я» → «9-я Парковая») в отображаемом адресе не
  выполняется (для сопоставления адресов между источниками это не имеет
  значения — используется устойчивый к порядку слов ключ, см.
  `addresses.py`); при необходимости адрес можно поправить вручную.
- Персональный адресный блок строится, когда поле «Руководитель
  управляющей компании» раскладывается ровно на «Фамилия Имя Отчество»
  (с учётом типичных префиксов вида «ГЕНЕРАЛЬНЫЙ ДИРЕКТОР: ...», см.
  `formatting.parse_director_field`); если данные в справочнике не
  раскладываются (сокращения, ИФамилия и т.п.) — письмо формируется в
  обезличенном виде и помечается для проверки, как и предписывает ТЗ,
  раздел 9, для неоднозначных случаев.
- Результат подтверждённой проверки по ЕГРЮЛ кэшируется в отдельном
  локальном JSON-файле приложения, а не дописывается автоматически в
  Excel-файл справочника пользователя — чтобы не рисковать испортить
  формат исходного файла. Реестр УК/ТЦ при этом обновляется «эффективно»:
  при следующей генерации по тому же адресу данные ЕГРЮЛ подставляются
  из кэша без повторного запроса.
